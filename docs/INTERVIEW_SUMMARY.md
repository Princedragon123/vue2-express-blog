## Q3: 描述一个你修复的 Bug

**回答思路（选最亮眼的）：**

**安全漏洞 — 确认密码验证失效**

> 在 `authController.js` 中发现了一个安全问题：注册时确认密码的验证永远通过。
>
> ```javascript
> // Bug 代码
> await registerValidation.validate({
>   username, email, password,
>   confirmPassword: password  // ← BUG: 永远和密码相同
> });
> ```
>
> 原因：`confirmPassword` 被赋值为 `password` 本身，Yup 的 `.oneOf([yup.ref('password')])` 校验形同虚设。
>
> 修复：改为 `confirmPassword: req.body.confirmPassword`，从用户输入获取。
>
> 这个问题如果上线，所有用户注册时输错确认密码都不会被拦截。

## Q4: 移动端适配你做了什么？

**回答思路：**

> 这个项目原本桌面端功能完整，但移动端存在几个关键问题：
>
> 1. **导航缺失** — TopNavbar 的汉堡菜单 CSS 写了但 HTML 没渲染，移动端用户无法导航
>    - 解决：新增汉堡按钮 + 右侧滑入抽屉菜单（动画、遮罩、安全区适配）
>
> 2. **安全区不适配** — iPhone X 以上的底部导航栏被 Home Indicator 遮挡
>    - 解决：`padding-bottom: env(safe-area-inset-bottom, 8px)`
>
> 3. **消息页布局** — 桌面端联系人+聊天窗口并排，移动端空间不够
>    - 解决：微信式布局 — 联系人全屏 ⇄ 聊天窗从右侧滑入
>
> 4. **文章详情互动按钮** — 桌面端夹在内容中间，移动端不方便操作
>    - 解决：移动端底部固定互动栏（点赞/评论/收藏/分享）
>
> 5. **搜索无历史** — 用户每次都要重新输入
>    - 解决：localStorage 持久化搜索历史（最多 10 条，可一键清空）

## Q5: 你做了哪些性能优化？

**回答思路：**

> 1. **JWT 载荷缓存** — `getUserRole` getter 之前每次访问都做 `atob` + `JSON.parse`，现在加缓存层，同 token 只解析一次
> 2. **滚动监听合并** — Blog.vue 原来有两个独立的 `scroll` 事件监听器（无限滚动 + 回到顶部），合并为一个，且加了 `passive: true`
> 3. **搜索防抖** — 搜索输入从每次按键都发请求改为 350ms 防抖
> 4. **Webpack 文件系统缓存** — 二次构建从 ~14s 降到 ~3.7s（提升 73%）
> 5. **SplitChunks 优化** — element-ui 和 quill 独立打包，首屏加载减少约 15%

## Q6: 如果重新做，你会怎么做？

**回答思路（展示反思能力）：**

> 1. **先写测试** — 这次是在已有代码上优化，如果有测试覆盖，改起来更放心
> 2. **分多次 PR** — 一次改动 35 个文件太多了，Review 困难。应该分：
>    - PR1: Bug 修复（3 个文件）
>    - PR2: 移动端导航（2 个组件）
>    - PR3: 消息页重构（1 个组件）
>    - 以此类推
> 3. **Component 拆分更早做** — Blog.vue 601 行、Create.vue 581 行，应该在组件变复杂之前就拆分
> 4. **TypeScript** — 这个项目是纯 JS，重构时容易因为拼写错误引入 Bug（比如 API 路径写错），TS 可以在编译时就发现
